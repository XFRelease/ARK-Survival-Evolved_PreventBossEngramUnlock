第一章 · 软件总览

软件总览

这是「先锋.禁止BOSS解锁印痕」——一个方舟生存进化服务端 ArkApi 插件。它在 BOSS 恐龙死亡瞬间清空其自带的奖励印痕列表，使参与击杀的玩家不再自动解锁对应印痕（如泰克科技印痕）；BOSS 本身照常死亡，战利品、经验等一切照旧。

🦖

拦截BOSS击杀印痕

BOSS 死亡瞬间清空奖励印痕列表，玩家不再自动解锁泰克等 BOSS 印痕。

⚔️

不影响BOSS战与掉落

BOSS 照常死亡，战利品、经验、战斗流程原样放行，只拿走「自动解锁印痕」。

🎚️

单键开关

config.json 一个 true / false 决定开与关，配置缺失或类型错误时安全放行。

🔄

配置热重载命令

控制台 / RCON 执行 Reload 命令，改完开关免重启立即生效。

🛠️

一键编译与部署脚本

工程自带编译（测试版 / 正式版）、一键安装、一键清除、一键附件脚本。

📝

编码自适应日志

3.54 / 3.55 服务器控制台通吃，横幅、调试、错误信息不乱码。

第三章 · 部署安装

部署安装

以下为拿到编译好的插件后在服务器上的部署步骤，插件英文名为 PreventBossEngramUnlock。

  1. 确认服务器已安装 ArkApi

    检查服务器目录 ShooterGame\Binaries\Win64\ArkApi\ 是否存在 → 存在则继续；不存在请先安装 ArkApi（最低 3.5）。

  2. 复制插件文件

    把 PluginInfo.json、config.json、PreventBossEngramUnlock.dll 复制到 ShooterGame\Binaries\Win64\ArkApi\Plugins\PreventBossEngramUnlock\ → 目录不存在时先创建（工程自带的 一键安装.bat 会自动完成复制与建目录，并可选择同时部署停用副本 PreventBossEngramUnlock.dll.arkapi）。

  3. 检查配置文件

    打开插件目录下的 config.json，确认内容为合法 JSON、且 Settings.PreventUnlockEngram 为 true → 配置详解见第四章。

  4. 重启服务器

    启动方舟服务器 → 服务器控制台出现「先锋.禁止BOSS解锁印痕(1.0) 先锋方舟服主群:138535385 作者QQ:711919」横幅日志即表示插件加载成功；测试版插件随后还会输出一行「调试输出,测试编码」自检（正式版不输出该行），这行中文显示正常就说明控制台编码匹配。若控制台出现红色「钩子安装失败」提示，见第六章常见问题。

  5. 验证功能

    在服务器控制台或 RCON 执行 PreventBossEngramUnlock.Reload → 返回 Reloaded config 表示命令可用；游戏内击杀任意 BOSS，参与击杀的玩家不再自动解锁 BOSS 奖励印痕即功能生效（测试版插件还会在控制台输出一行「---->BOSS死亡, DeathGiveEngramClasses数量=N」调试日志，正式版不输出）。

若 config.json 缺失或不是合法 JSON，插件加载时会抛出错误 Can't open config.json（源码 Main.cpp 的 ReadConfig()），插件将无法正常启动。部署前务必确认配置文件存在且格式正确。
编译产物位于工程 Output\PreventBossEngramUnlock\ 目录；首次使用编译脚本前需先运行 环境变量.bat 设置 ASE_API（用户级永久环境变量，重启命令行 / VS 后生效）。

第四章 · 配置详解

Settings.PreventUnlockEngram 功能开关

什么意思：插件唯一的功能开关，决定「击杀 BOSS 是否自动解锁奖励印痕」。插件在每只 BOSS 恐龙死亡时读取此值：true 表示拦截——清空 BOSS 的奖励印痕列表，参与击杀的玩家不再自动解锁（如泰克科技印痕）；false 表示放行——完全恢复原版行为。

兜底值：功能关闭（该键缺失、Settings 不是对象、或值不是 true / false 布尔值时，插件一律不拦截，等价 false，服务器按原版运行）

{
  "Settings": {
    "PreventUnlockEngram": true
  }
}

怎么修改：只能填 true 或 false（小写，不要加引号）。改完在控制台 / RCON 执行 PreventBossEngramUnlock.Reload 立即生效，无需重启服务器；从下一次 BOSS 被击杀起按新值执行。

拦截范围以游戏自身的 BOSS 判定为准（源码调用 IsBossDino()）：所有被游戏判定为 BOSS 的恐龙都在范围内。该开关只影响「死亡时自动解锁印痕」，不影响 BOSS 死亡本身、战利品与经验，也不会收回玩家已解锁的印痕。
第四章 · 配置详解

ConsoleEncoding 控制台编码

什么意思：控制插件往服务器控制台输出文字时用的编码。不同版本 ArkApi 的服务器控制台编码不同（3.54 为 GBK/ANSI，3.55 为 UTF-8），编码不匹配时控制台中文会乱码。本插件输出前会按这个配置决定是否把 UTF-8 转成 GBK（Main.cpp 的 应用控制台编码配置，插件日志模块 h/日志.h 的自动输出系列同受其控制）。

兜底值：auto（配置缺失或值非法时都按 auto 处理，非法值会在控制台提示一行黄色警告）

{
  "ConsoleEncoding": "auto"
}

怎么修改：可选值共三个（大小写不限）：

取值效果
auto自动探测：控制台代码页为 936 时转 GBK 输出，否则按 UTF-8 原样输出。3.54 / 3.55 服务器都不用改配置，推荐保持默认
gbk强制输出前转 GBK（等同旧版行为；写 ansi 也可以）
utf8强制 UTF-8 原样输出（写 utf-8 也可以）
改完不用重启：控制台 / RCON 执行 PreventBossEngramUnlock.Reload 即可热生效（编码解析在每次读取配置时进行）。

第六章 · 常见问题

常见问题

击杀 BOSS 后没解锁印痕（如泰克），是出 BUG 了吗？
不是 BUG，这正是本插件的功能。确认 config.json 中 Settings.PreventUnlockEngram 为 true，即插件在按配置工作。
怎么临时恢复「击杀 BOSS 自动解锁印痕」？
先试这个：把 Settings.PreventUnlockEngram 改为 false，执行 PreventBossEngramUnlock.Reload 热重载，无需重启；也可以停用插件（见下方「怎么临时停用插件」）。
服务器原有 config.json 没有 Settings 键，升级插件后功能没生效？
先试这个：配置缺失该键时插件按「关闭」处理（安全放行）。手动在 config.json 顶层补上 "Settings": { "PreventUnlockEngram": true } 后执行 Reload。注意 一键安装.bat 会用工程输出目录的 config.json 整体覆盖服务器上的同名文件，若服务器配置被手工定制过，建议手动补键而不是覆盖。
插件会影响 BOSS 的掉落、经验或战斗流程吗？
不会。插件只清空 BOSS 死亡时的奖励印痕列表，BOSS 的死亡流程、战利品与经验全部原样放行；玩家此前已解锁的印痕也不会被收回。
控制台出现红色「钩子安装失败」提示？
这表示插件与服务器上的 ArkApi 版本不匹配（钩子函数寻址失败）。此时插件的拦截功能不会生效，但服务器其余运行不受影响。请核对 ArkApi 版本（要求 3.5+）并联系作者反馈。
控制台中文乱码（方块/问号）？
先试这个：测试版插件启动时会输出一行「调试输出,测试编码」自检——这行中文显示正常就说明编码匹配（正式版无此行，可看加载横幅的中文是否正常）；若乱码，保持 ConsoleEncoding 为 auto 并执行 PreventBossEngramUnlock.Reload；仍乱码再按 ArkApi 版本显式指定——3.54 服务器设 gbk、3.55 服务器设 utf8。
插件没加载，控制台提示 Can't open config.json？
先试这个：检查 ArkApi\Plugins\PreventBossEngramUnlock\config.json 是否存在、文件名拼写是否正确；存在则用 JSON 校验工具检查格式（多逗号、缺引号都会导致解析失败）。
改了 config.json 但没生效？
先试这个：在控制台或 RCON 执行 PreventBossEngramUnlock.Reload 热重载；若提示 Failed to reload config 说明新配置格式有错，按报错修正后重试。仍不生效则重启服务器。
配置文件放哪里？
插件目录固定为 ShooterGame\Binaries\Win64\ArkApi\Plugins\PreventBossEngramUnlock\config.json，与 PreventBossEngramUnlock.dll 同目录。
怎么临时停用插件？
把插件目录下的 PreventBossEngramUnlock.dll 改名为 PreventBossEngramUnlock.dll.arkapi（ArkApi 不加载该后缀），重启服务器即可停用；改回 .dll 恢复。工程的 一键安装.bat 也支持部署停用副本。
编译脚本报错找不到 ArkApi？
先试这个：运行工程目录下的 环境变量.bat 设置 ASE_API 环境变量指向 ServerAPI 目录（默认探测 D:\ASE\ServerAPI），设置后重新打开命令行 / VS 再编译；并确认 ServerAPI 已运行其 build.bat 生成 ArkApi.lib。
